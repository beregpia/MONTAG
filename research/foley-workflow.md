# Разбор реальной сессии Pro Tools и регистрация фоли-дубля

> Дата: 30 октября 2026. Пользователь прислал два скриншота рабочей сессии
> (Pro Tools, позиция 00:02:29:11). Ниже — что из них следует для движка,
> и прототип **приведения записанного дубля к кадрам контакта стопы**
> (`tools/align-pass.mjs`), который закрывает главный ручной труд.

---

## 1. Что видно в сессии

**Структура дорожек** (по имени — категория, это и есть разметка):

| Группа | Дорожки | Что это, судя по имени |
| --- | --- | --- |
| Диалог | `HFIMS_TR_FORAKINAVO`, `DELAL DOP 1-3`, `DOP4`, `DOP5` | производственный звук / диалог |
| Дверь | `Door`, `DOOR` | дверь, два дубля |
| Руки | `HEANDS1-9` | «хендс» — работа рук (несколько проходов) |
| Реквизит | `requisite1-9` | реквизит, 9 проходов |
| Ткань | `CLOTH 1-3` | одежда/ткань |
| Шаги | `STEP`, `STEP NATALI`, `STEP 3`, `STEP33`, `STEP 2`, `STEP 4-9` | **шаги, много проходов** |
| Опоры | `Audio 5` | ? |
| Таймкод | `FreeFrames` | дорожка таймкода/маркеров |

**Что там происходит:** клипы уже расставлены по таймлайну, то есть редактор
вручную вырезал отдельные шаги/удары из записанных проходов и разложил их по
кадрам. На дорожках `STEP`, `requisite`, `CLOTH` видны длинные проходы,
разрезанные на десятки мелких клипов. Часть дорожек заглушена (`M`) или на
записи (`Q`).

**Масштаб:** сессия на 2:29 — это полнометражный материал, то есть ~90 минут
работы ровно того характера, о котором мы договаривались.

## 2. Что это меняет в архитектуре

1. **Категория звука берётся из имени дорожки.** Это подтверждает вывод из
   `research/foley-engine.md` §3А: классификатор не нужен, дорожка `STEP` =
   шаги, `CLOTH` = ткань, `requisite` = реквизит. Движок должен **читать имена
   дорожек и сохранять их** в результатах, а не придумывать свои метки.

2. **Единица работы — не «звук из библиотеки», а «проход».** Артист записывает
   проход (серию шагов, серию ударов), а редактор режет его на события. Значит
   ядро движка — не подбор звука по описанию, а **приведение прохода к картинке**.
   Именно это и сделано ниже.

3. **Основной ручной труд — это перенос.** Не «найти звук», а «взять Schritt из
   дубля и поставить в кадр контакта». Автоматизация ровно этого даёт максимум
   экономии.

4. **Именование в экспорте критично.** Раз редактор держит 9 дорожек `STEP` и 9
   `requisite`, экспорт должен нести имена дорожек/клипов (в AAF — имена
   клипов и дорожек), иначе организация сессии рассыпается.

5. **Нужен учёт таймкода сессии.** Дорожка `FreeFrames` и большие таймкоды
   (00:02:29:11) означают, что движок обязан работать в таймкоде проекта
   (fps, стартовый ТК), а не в «секундах от начала файла».

## 3. Прототип: регистрация прохода по кадрам контакта

`tools/align-pass.mjs` — берёт записанный дубль и список кадров контакта
(из видео-детектора) и выдаёт таблицу «куда вставить — откуда взять».

**Алгоритм:**
1. сегментация дубля на шаги (готовый детектор `js/onset.js`);
2. уточнение времени каждого шага **до отсчёта** — ищем первый момент, где
   сигнал превысил 15% пика и держится 3 мс (детектор даёт время кадра
   анализа, шаг 11.6 мс, плюс запаздывание атаки);
3. **динамическое программирование с полосой** — монотонное сопоставление
   «один к одному» с пропусками: лишний шаг артиста или пропущенный контакт;
4. линейная модель `t = k·s + d` — снимает накопившийся дрейф темпа
   (артист шёл 0.585 с на шаг, картинка 0.580 с → за 25 шагов 90 мс расхождения);
5. подбор `k` и `d` грубой 2D-сеткой, затем уточнение, затем МНК по
   согласованным парам.

### Замер на синтетическом дубле (26 шагов артиста vs 25 контактов на картинке)

```

  накопленный дрейф темпа за проход: 90 мс (2.3 кадра)

ТК на картинке   кадр стопа  взять из дубля              вырез   пара
  00:00:10:08    258     L          9.903с         9.85–10.20      ✓
  00:00:10:22    272     R         10.484с        10.43–10.78      ✓
  ...
  00:00:24:05    605     L         23.905с        23.85–24.20      ✓

Соответствие: размещено 25 из 25 контактов · незакрытых 0 · лишних шагов в дубле 1

```

**Результат: 25 из 25 контактов закрыты, лишний шаг артиста (16.60 с) правильно
опознан и не использован, одна пара помечена «проверить вручную».**

### Важный вывод про «ошибку»

Первая версия алгоритма (жадный поиск) «съезжала на шаг»: при почти
периодических шагах гистограмма разностей даёт несколько равноценных пиков, и
жадный выбор цеплял неверное соответствие — из-за этого весь конец прохода
уезжал (18 из 25, а 7 контактов оставались без дубля). DP с монотонностью и
пропусками лечит это полностью. **Это была бы самая дорогая ошибка в бою:**
молча неверная расстановка выглядит правдоподобно.

Второй вывод — про метрику. «Остаток модели» (средний 24.5 мс, макс 61 мс) —
это **не** ошибка синхронности. Звук вырезается из дубля в его собственной
точке и вставляется в кадр контакта, поэтому точность расстановки ограничена
только точностью определения кадра контакта на картинке. Остаток показывает
лишь, насколько линейная модель уверена в паре — и используется как флаг
«проверить вручную», а не как оценка качества.

## 4. Что осталось до рабочего контура

1. **Видео-детектор кадров контакта** — вторая половина входа для
   `align-pass.mjs` (сейчас контакты берутся из фикстуры). Начинать с L0:
   оптический поток по зонам сетки, без ML.
2. **Чтение дорожек из сессии** — имена дорожек как категории, таймкод и fps
   проекта (из `FreeFrames`/настроек сессии).
3. **Экспорт результата** в трёх форматах: SMF-маркеры контактов (Cubase/
   Nuendo — готово), CSV/XML с таймкодами (Pro Tools через EdiMarker),
   **AAF/OMF с расставленными клипами** — для их рабочего процесса это самый
   ценный формат, потому что сразу даёт дорожки с клипами.
4. **Выбор варианта среди проходов** — когда на сцену есть 9 дорожек `STEP`,
   движок должен предлагать, какой проход взять, и не повторять один и тот же
   шаг подряд (дескрипторы веса/материала из `tools/foley-library.mjs`).
