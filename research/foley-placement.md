# Размещение фоли: открытые категории и два режима работы

> Дата: 30 октября 2026. Уточнение по вашей сессии: `HEANDS` = **руки**, и
> категорий будет больше (доп-звуки). Отсюда требование: **движок не должен
> знать список категорий заранее.** Плюс два принципиально разных способа
> записать дубль, и от этого зависит, каким алгоритмом размещать.
> Прототип: `tools/place-foley.mjs` + `tools/foley-library.mjs`.

---

## 1. Открытая таксономия

Категория — это **строка из имени дорожки**, а не пункт в коде. Добавили в
сессии дорожку `metal` — движок разместил события этой категории, ничего не
меняя в программе.

```js
const PROFILES = {
  steps: { weights: {...}, minGap: 0.3,  visual: 'foot-contact' },
  hands: { weights: {...}, minGap: 0.12, visual: 'hand-object-contact' },
  cloth: { weights: {...}, minGap: 0.2,  visual: 'motion-region' },
  door:  { weights: {...}, minGap: 0.3,  visual: 'impact' },
  default: { weights: {...}, minGap: 0.15, visual: 'motion-region' },  // всё остальное
};
const profileOf = (c) => PROFILES[c] || PROFILES.default;
```

Профиль задаёт только **настройки**, а не поведение: веса дескрипторов при
сопоставлении и `min-gap` при сегментации (у рук события чаще, чем у шагов —
поэтому у них порог 0.12 с против 0.30 с). Неизвестная категория получает
общий профиль и работает нормально.

**Проверено:** в демо 6 категорий на картинке, 5 дорожек. `metal` в `PROFILES`
отсутствует — оба события размещены. `paper` без дорожки — движок называет это
прямо: `ДОРОЖКИ НЕТ — нужна запись`, а не молча подставляет что-то не то.

```
  metal      событий   2 · размещено   2 · уникальных дублей   2 из   3  все события без повторов
  steps      событий   8 · размещено   8 · уникальных дублей   6 из   8  повторов 2 (дублей 6 на 8 событий)
  hands      событий   7 · размещено   7 · уникальных дублей   5 из   7  повторов 2 (дублей 5 на 7 событий)
  cloth      событий   5 · размещено   5 · уникальных дублей   5 из   6  все события без повторов, дубли остались
  door       событий   1 · размещено   1 · уникальных дублей   1 из   2  все события без повторов, дубли остались
  paper      событий   1 · размещено   0 · уникальных дублей   0 из   0  ДОРОЖКИ НЕТ — нужна запись
```

Два поведения, которые важны на бою:
- **нехватка дублей называется числом.** «Повторов 2» = редактору надо записать
  ещё варианты, и он видит это до того, как начнёт собирать сцену;
- **повторы не идут подряд.** Коолдаун: один и тот же дубль не используется
  повторно в пределах 4 ближайших событий своей категории — иначе шаги
  «заедают» и фон становится искусственным.

## 2. Два режима записи — и два разных алгоритма

Это главное архитектурное решение, и оно следует из вашей сессии: у вас 9
дорожек `STEP` и 9 `requisite`, то есть **проходов много**, и они разные.

### Режим А. «Проход» — артист записывал, глядя на картинку
Записанная серия шагов **примерно совпадает** с картинкой по времени.
Размещение — **регистрация прохода**: найти соответствие «шаг дубля → кадр
контакта» и вставить каждый шаг в свой кадр. Реализовано в
`tools/align-pass.mjs` (25 из 25 контактов, лишний шаг артиста опознан —
`research/foley-workflow.md` §3).

Здесь **сохраняется игра артиста**: он шёл не идеально ровно, и эта
неравномерность часть фоли. Алгоритм её не выпрямляет.

### Режим Б. «Библиотека» — записаны варианты, не привязанные к картине
Набор дублей: 6 шагов по гравию разной силы, 3 металлических щелчка. Любой
может встать в любое место, выбор — **по дескрипторам**: сила, полоса,
спектральный центроид, длительность. Реализовано в `tools/place-foley.mjs`.

### Почему это разные инструменты, а не один

| | Режим А (проход) | Режим Б (библиотека) |
| --- | --- | --- |
| Что на входе | один дубль + кадры контакта | много дублей + события картинки |
| Что решает | соответствие шаг↔кадр | какой дубль подойти к событию |
| Ошибка = | съезд на шаг (лечится DP) | не тот по силе/материалу |
| Сохраняет игру артиста | **да** | нет |
| Когда в сессии | длинные проходы `STEP 2`, `CLOTH 1` | `requisite`, `Door`, отдельные дубли |

В реальной сцене обычно **оба**: проход регистрируется по контактам, а
реквизит и руки подбираются из библиотеки. Движок должен уметь спрашивать
«этот дубль записан по картинке?» и выбирать режим сам.

## 3. Контур целиком (проверен, `npm run place-demo`)

```
 tools/make-place-fixture.mjs      → дорожки сессии (по файлу на категорию)
                                      + события на картинке
 tools/foley-library.mjs (×N)      → индекс каждой дорожки: сегментация,
                                      дескрипторы, стопа L/R, темп
 tools/place-foley.mjs             → расстановка: кадр → файл, откуда резать
```

Каждая дорожка индексируется **своим** `min-gap` под свою категорию — у шагов
0.30 с, у рук 0.12 с, у ткани 0.20 с. Это прямое следствие того, что категории
приходят из дорожек.

Замер демо (24 события на картинке, 23 дубля в 5 дорожках): 23 из 24
размещены, единственное неразмещённое — категория без дорожки, названная
прямо. Время всего прогона — меньше секунды.

## 4. Что это даёт в вашем рабочем процессе

Сейчас редактор вручную: слушает проход → вырезает шаг → ставит в кадр →
правит. Движок берёт на себя «вырезать и поставить», оставляя человеку
«выбрать вариант и проверить». Конкретно:

1. **Шаги** — регистрация прохода по контактам (режим А), редактор проверяет
   помеченные пары и правит ±1 кадр там, где нужно;
2. **Руки, реквизит, дверь** — подбор из библиотеки по силе и материалу
   (режим Б), с защитой от повторов подряд;
3. **Нехватка дублей** — видна числом до начала сборки;
4. **Категория без дорожки** — называется прямо, а не подменяется похожей.

## Осталось

1. **Видео-детектор** — источник событий на картинке (сейчас фикстура). Начинать
   с L0: оптический поток по зонам сетки, без ML; профиль `visual` из таблицы
   выше подсказывает, что искать для каждой категории.
2. **Экспорт расстановки** — AAF/OMF с клипами на дорожках (самый ценный формат
   для вашего процесса), CSV/XML с таймкодами для EdiMarker, SMF-маркеры
   (готово).
3. **Выбор режима А/Б автоматически** — по длине дубля и наличию кадров контакта.
4. **Интерфейс подтверждения** — показ пары «дубль ↔ кадр» с прослушиванием,
   чтобы редактор соглашался пачкой, а не по одному.
