# MONTAG

Видеомонтажёр, который работает целиком в браузере: импорт клипов, таймлайн,
подрезка, переходы, превью в реальном времени и экспорт готового ролика в `.webm`.
Ничего не загружается на сервер — файлы остаются на вашем компьютере.

## Запуск — три способа

### 1. Проще не бывает: один файл (ничего устанавливать не нужно)

Скачайте файл [**montag-standalone.html**](montag-standalone.html) и откройте
его двойным кликом — это полная копия приложения в одном HTML-файле,
которая работает без интернета, без Node, без Python и без VS Code.

Ссылка на скачивание (последняя версия):

```
https://github.com/beregpia/MONTAG/raw/arena/c575b8e1-montag/montag-standalone.html
```

Браузер может спросить, что делать с файлом — выберите «Открыть» / «Сохранить
и открыть». Если открылась пустая страница, значит файл скачался как HTML-страница
просмотра GitHub: нажмите на странице `Ctrl+S` / `Cmd+S` и сохраните с именем
`montag-standalone.html`, затем откройте сохранённый файл.

> Весь интерфейс, код и стили уже внутри этого файла — интернет ему не нужен.
> Единственное ограничение: браузерные ограничения `file://`, поэтому некоторые
> сборки браузеров не дают такому файлу запускать запись видео. Если кнопка
> экспорта или «Демо-клип» не сработают — используйте способ 2 или 3.

### 2. Через локальный сервер (если нужен node)

```bash
node server.js    # или: npm start
```

Затем открыть http://localhost:8080

### 3. Собрать файл самостоятельно

```bash
npm install       # ставит jsdom (только для тестов)
npm run build     # esbuild → montag-standalone.html
```

## Быстрый старт

Откройте приложение (любым из трёх способов выше) и нажмите **🎬 Демо-клип** —
оно сгенерирует 8-секундное тестовое видео с шагами и щелчками, добавит его
на таймлайн, и можно сразу пробовать монтаж, фоли и экспорт, не имея
своих файлов.

Дальше: перетащите своё видео в окно (или «＋ Импорт видео»), нажмите
**«На таймлайн»** (или двойной клик по файлу в медиатеке) — и монтируйте.

## Если видео не загружается

Приложение работает полностью в браузере и открывает только те форматы,
которые умеет сам браузер: **mp4 (H.264 + AAC)** и **webm (VP8/VP9)**.
Файлы **mkv, ProRes, HEVC, avi** браузер прочитать не может — сконвертируйте
их в mp4 (HandBrake или `ffmpeg -i in.mov -c:v libx264 -c:a aac out.mp4`).

При неудачной попытке в панели «Медиа» появляется запись журнала
(✓ / ✕ с причиной). Частые причины:

| Причина | Что делать |
| --- | --- |
| «формат или кодек не поддерживается» | конвертировать в mp4 H.264 / webm |
| «выбраны не видеофайлы» | выбрать файл с расширением mp4/webm/mov |
| «таймаут чтения метаданных» | файл огромный или битый — попробуйте другой |
| Клип не появился на таймлайне | импорт ≠ таймлайн: нажмите «На таймлайн» или двойной клик по файлу |

## Возможности

- **Импорт** — перетащите видео в окно или нажмите «Импорт видео» (mp4, webm, mov).
  Двойной клик по файлу в медиатеке добавляет его на таймлайн.
- **Таймлайн** — клипы выстраиваются в последовательность, перетаскиваются
  мышью для смены порядка, удаляются кнопкой или клавишей `Delete`.
  Зум `＋ / −`, клик по линейке — переход к позиции.
- **Подрезка** — в инспекторе справа задаются точки «Начало» / «Конец» клипа.
- **Переходы** — между клипами: без перехода, кроссфейд или «через чёрный».
- **Звук** — громкость каждого клипа + общая мастер-шина (Web Audio).
- **Разделение** — кнопка «✂ Разделить» или клавиша `S` режет клип
  в позиции playhead.
- **Экспорт** — кнопка «⏺ Экспорт видео» собирает ролик в `.webm`
  (VP9/VP8 + Opus) и скачивает его. Запись идёт в реальном времени,
  поэтому ролик длиной 1 минута экспортируется ~1 минуту.
- **Проект** — «Проект ↓ / ↑» сохраняет и открывает монтаж в JSON
  (видео нужно импортировать повторно — файлы не хранятся внутри проекта).

## Горячие клавиши

| Клавиша | Действие |
| --- | --- |
| `Пробел` | пуск / пауза |
| `S` | разделить клип в позиции playhead |
| `←` / `→` | ±1 с (`Shift` — ±5 с) |
| `Home` / `End` | в начало / в конец |
| `Delete` | удалить выбранный клип |

## 🎙 Foley — синхронизация звука с видео

Кнопка **🎙 Foley** в верхней панели открывает панель фоли-озвучки: шаги, руки,
предметы и другие шумы контакта, синхронизированные с картинкой.

**Как работает:**

1. **Анализ** — выберите файл-источник и нажмите «Анализировать аудио».
   Звуковая дорожка декодируется и прогоняется через детектор моментов
   контакта: STFT (собственная FFT, окно Ханна) → спектральный флюкс →
   пики с адаптивным порогом. Каждое событие классифицируется по диапазону:
   `низкий` (шаги, удары, предметы), `средний` (ткань, взмахи), `высокий`
   (щелчки, пластик). Ползунки «Порог детекта» и «Мин. интервал» пересчитывают
   анализ на лету.
2. **Перенос** — «Перенести события на таймлайн» расставляет фоли-события
   с учётом in-точек клипов (если клип обрезан, события внутри обрезки
   не попадают) и авто-подбирает звук по диапазону и силе.
3. **Подгонка** — у каждого события: выбор звука из библиотеки, сдвиг
   **на кадр** кнопками `−1к / +1к` (точность = 1/fps, по умолчанию 33 мс
   при 30 fps), громкость, прослушивание в контексте таймлайна.
   События-маркеры видны на отдельной дорожке под клипами.
4. **Микшер** — общая громкость фоли-шины; при экспорте фоли-звук
   попадает в запись автоматически (шина подключена к мастер-каналу).

**Библиотека звуков** синтезируется процедурно (шум + однополюсные фильтры +
синусы с огибающими) — внешние сэмплы не нужны: шаг, тихий шаг, каблук,
туду, ткань/руки, шелест, касание, взмах, клик, металл/пластик. При
   срабатывании к каждому звуку применяется лёгкая вариация темпа, чтобы
   серия шагов не звучала «заедающим» сэмплом.

**Синхронизация:** триггер срабатывает в кадре, где playhead пересекает время
   события; задержка кадра (~16 мс) компенсируется смещением внутрь буфера
   звука, так что попадание практически покадровое. Перескоки (seek) не
   запускают всю серию звуков подряд.

**Ограничения:** браузер должен уметь декодировать аудио из вашего файла
   (mp4/AAC, webm/Opus — обычно умеют). Анализ файлов >200 МБ может занять
   десятки секунд. Экспорт фоли идёт в реальном времени вместе с роликом.

## 🎛 Мост в DAW: маркеры для Cubase

Если финальная сборка идёт в **Cubase** (или Nuendo), маркеры моментов
контакта можно выгрузить в Standard MIDI File: панель Foley →
**«⇩ Экспорт маркеров в MIDI (.mid)»**. Файл пишется с темпомапой
**1 тик = 1 мс**, поэтому позиции маркеров попадают в проект с точностью
до 1 мс (~1/33 кадра при 30 fps).

В Cubase: `Preferences → MIDI → MIDI File → Import Markers` →
`File → Import → MIDI File` → маркеры становятся маркерами проекта.
Дальше включается Snap типа **Events** (маркеры и внутренние точки привязки
аудио-событий магнитятся), и фоли-клипы перетаскиваются к маркерам прямо
на дорожках. Подробный разбор со всеми меню, способами выравнивания
(по началу события и по внутренней точке через `Audio → Snap Point to Cursor`),
тонкой подгонкой в Info Line и массовым сдвигом через Project Logical Editor —
в **[cubase/ALIGNMENT.md](cubase/ALIGNMENT.md)**.

> Почему не VST3 и не скрипт: VST3 обрабатывает только свой аудиопоток
> и не может двигать клипы других дорожек; в Cubase нет публичного API
> для аранжировки. Поэтому в Cubase рабочий путь — маркеры + Snap,
> а позиции считает детектор MONTAG.

## Технологии

Чистый фронтенд без сборки и зависимостей: ES-модули, Canvas 2D,
Web Audio API, `canvas.captureStream()` + `MediaRecorder`.
Рекомендуемые браузеры — Chrome, Edge или Firefox.

## Структура

```
index.html        — разметка интерфейса
css/style.css     — оформление (тёмная тема)
js/state.js       — состояние проекта, раскладка таймлайна, шина событий
js/media.js       — импорт файлов, превью-кадры, медиатека
js/timeline.js    — дорожка, плейхед, drag & drop, зум, дорожка фоли
js/inspector.js   — параметры выбранного клипа
js/player.js      — движок превью: композитинг кадров и аудиограф
js/recorder.js    — экспорт в .webm
js/project.js     — сохранение / открытие проекта (JSON)
js/main.js        — точка входа
js/fft.js         — быстрое преобразование Фурье (radix-2)
js/onset.js       — детект моментов контакта (spectral flux)
js/sfx.js         — процедурный синтез фоли-звуков
js/foley.js       — фоли-движок: анализ, размещение, триггеры
js/foley-panel.js — панель Foley
js/midi.js        — запись Standard MIDI File с маркерами (мост в DAW)
js/demo.js        — генератор демо-клипа (canvas + MediaRecorder)
server.js         — статический сервер для разработки
build-standalone.mjs — сборка montag-standalone.html (esbuild, только для сборки)
tests/            — автотесты: `npm test` (8 наборов, jsdom)
cubase/ALIGNMENT.md — руководство по синхронизации фоли по дорожкам в Cubase
montag-standalone.html — собранное приложение в одном файле (открывается двойным кликом)
```

## Тесты

```bash
npm install     # ставит jsdom (нужен только для тестов)
npm test        # 8 наборов: ядро, синтез, MIDI, приложение, фоли, импорт, демо, сборка
```

| Набор | Что проверяет |
| --- | --- |
| `tests/core.mjs` | FFT (Парсеваль, точность бинов), детектор контактов (точность < 60 мс, чувствительность, minGap) |
| `tests/sfx.mjs` | все 10 фоли-звуков: длина, пик 0.85 без клиппинга, детерминизм по seed |
| `tests/midi.mjs` | SMF: формат 0, PPQ 480, 1 тик = 1 мс, позиции маркеров с точностью 1.5 мс, 500 маркеров |
| `tests/app.mjs` | раскладка таймлайна, кроссфейды, рендер, инспектор, разделение, удаление, проект (39 проверок) |
| `tests/foley.mjs` | анализ → размещение с учётом in-точек, сдвиг на кадр, триггеры без дребезга и без «залпа» на seek, экспорт `.mid` (34 проверки) |
| `tests/media.mjs` | фильтр форматов, журнал импорта, тексты ошибок кодеков, «На таймлайн» |
| `tests/demo.mjs` | сценарий и кадры демо, отсутствие `requestAnimationFrame` (зависание в фоне), watchdog |
| `tests/standalone.mjs` | собранный файл: нет внешних ссылок, интерфейс поднимается, клики работают |

Тесты работают без браузера: HTML разворачивается в jsdom с заглушками
Web Audio / Canvas / MediaRecorder (`tests/helpers.mjs`), поэтому весь путь
«импорт → таймлайн → фоли → экспорт маркеров» проверяется в CI.


## Приложение для Windows

Два способа — от самого простого к настоящему `.exe`.

### 1. Без установки (100 КБ, работает сразу)

Положите `MONTAG.bat` и `montag-standalone.html` в одну папку и запустите
**двойным щелчком `MONTAG.bat`**. Откроется окно без адресной строки и вкладок —
выглядит как обычная программа. Node и интернет не нужны.

> Если Windows покажет предупреждение «Не удалось распознать издателя» —
> нажмите «Подробнее → Выполнить в любом случае». Файл из интернета, потому
> пометка. Либо: правый клик → Свойства → поставить галку «Разблокировать».

### 2. Настоящий `.exe` (~200 МБ)

```bash
npm install
npm run build
npm run build:win
```

Результат — папка `dist/MONTAG-win32-x64/` с файлом `MONTAG.exe` внутри.
Зазипкуйте её и перенесите на любой Windows: Node там не нужен, интернет тоже.

Что происходит: `electron/main.js` открывает `montag-standalone.html`
(в нём всё инлайном, поэтому работает по `file://` без сервера),
`electron/build-win.mjs` пакует это вместе с рантаймом Electron.

Собрать можно и на Linux/Mac — `--platform=win32` даёт Windows-версию.
